# ИИ-агент проверки домашки по математике (прототип)

Фото домашней работы → найденные ошибки с объяснениями → задания для работы над ошибками.

## Запуск

1. Получи ключ Claude API: https://console.anthropic.com/settings/keys
2. Скопируй `.env.example` в `.env` и вставь ключ.
3. Установи зависимости и запусти (проект использует uv, как и metrica-backend):

```bash
uv sync
uv run uvicorn main:app --reload
```

или через pip:

```bash
pip install "fastapi[all]" anthropic python-dotenv
uvicorn main:app --reload
```

4. Открой http://127.0.0.1:8000 — загрузи фото, жми «Проверить работу».

API напрямую: `POST /api/check`, multipart-поля:
- `photo` — фото решения ученика, JPEG/PNG/WebP/GIF/HEIC до 5 МБ (HEIC с
  iPhone конвертируется в JPEG на сервере);
- `task_photo` — необязательное фото условия задания (если на фото решения
  само условие не видно — например, ученик решал во второй тетради);
- `mode` — `school` (по умолчанию) или `ege_profile`;
- `student_id` — обязательное имя/ID ученика (свободный текст). Нужно, чтобы
  копить домашки и ошибки одного ученика между проверками — при переносе в
  metrica-backend заменяется на реальный `user_id` из системы аккаунтов.

Ответ — JSON по схеме `HomeworkReview` (см. `ai_checker/schemas.py`), с
добавленными `homework_number`/`homework_label` (например, `"дз3: задачи+уравнения"`
— тип классифицируется моделью автоматически по каждому заданию).

## Прогресс ученика за период

- `GET /api/students/{student_id}/homeworks` — история проверенных домашек
  ученика (номер, ярлык, дата, summary).
- `GET /api/students/{student_id}/progress` — сводка по накопленным ошибкам:
  модель группирует их по смыслу в темы (`"задачи:экономика"`,
  `"уравнения:материал 10 класса"`) и пишет narrative о прогрессе.
  Доступна с первой же домашки, но `threshold_reached=true` только когда
  занятий набралось 10 (`ai_checker/taxonomy.py:PROGRESS_REPORT_THRESHOLD` —
  в проде это будет календарный месяц). Результат кэшируется в БД до
  следующей новой домашки — повторные вызовы бесплатны.

Хранилище — SQLite (`ai_checker/storage.py`), файл `metrica_ai_checker.db`
в корне проекта (в `.gitignore`, при переносе в metrica-backend заменяется
на настоящие таблицы через Alembic).

## Режим «ЕГЭ профиль»

В режиме `ege_profile` агент дополнительно:
- определяет номер задания ЕГЭ (№1-19) и оценивает по критериям ФИПИ
  (`estimated_score` / `max_score` + обоснование);
- проверяет полноту обоснований: отбор корней в №13, ОДЗ в №15,
  доказательства в №14/№17, полноту случаев в №18 — и перечисляет пробелы
  в `justification_gaps`, даже если ответ верный;
- включает extended thinking (модель сначала сама прорешивает задачу) —
  разбор занимает 1-3 минуты и стоит дороже (~$0.10-0.20 за работу);
- тренировочные задания генерирует в формате реальных задач ЕГЭ.

## Структура

```
ai_checker/
  schemas.py    # Pydantic-схемы результата (ошибки, задания, прогресс)
  taxonomy.py   # типы заданий + порог "занятий" для сводки прогресса
  prompts.py    # промпты агента (проверка домашки + анализ прогресса)
  service.py    # вызовы Claude API, независим от FastAPI
  storage.py    # SQLite-персистентность (домашки, ошибки, кэш сводок)
  router.py     # FastAPI-роутер: /check, /students/{id}/homeworks, /progress
main.py         # точка входа + тестовая страница
static/index.html
```

## Интеграция в metrica-backend

Модуль писался под перенос:

1. Скопировать пакет `ai_checker/` в `src/` бэкенда.
2. Подключить роутер: `app.include_router(ai_router, prefix="/api/ai")` —
   или вызвать `review_homework()` из обработчика `/tutor/submissions/{id}`,
   передав байты файла сабмишена из `uploads/`.
3. Добавить `anthropic` в зависимости, `ANTHROPIC_API_KEY` — в окружение
   (docker-compose).
4. Дальше — таблица `ai_reviews` (Alembic-миграция) для хранения результатов
   и вывод разбора в TutorHomework/StudentDashboard на фронте.

## Бесплатный вариант (Qwen и другие open-source модели)

В `.env` переключи `AI_PROVIDER=openai_compat` — весь остальной код общий.
Два пути (примеры настроек — в `.env.example`):

**OpenRouter** — облачный API, есть бесплатные модели (`:free` в названии),
например Qwen-VL. Регистрируешься на openrouter.ai, берёшь ключ, карта не
нужна. Ограничение — лимит запросов в день, для теста хватает. Актуальный
список бесплатных vision-моделей смотри на openrouter.ai/models (фильтр free).

**Ollama** — модель работает локально на твоём компьютере: `ollama pull
qwen2.5vl:7b` и никакого интернета/оплаты. Нужно ~8 ГБ ОЗУ; разбор одного
фото на CPU может занимать несколько минут.

Честное предупреждение: бесплатные модели заметно слабее в математике —
чаще сами ошибаются в решениях (особенно ЕГЭ, вторая часть) и хуже
разбирают почерк. Extended thinking в режиме ЕГЭ у них тоже нет. Рабочая
стратегия: отлаживать систему на бесплатной модели, а в продакшене
использовать Claude — или дать пользователю выбор «быстро/бесплатно» vs
«точно/платно».

## Стоимость

Один разбор фото — примерно $0.02–0.06 на claude-sonnet-5 (зависит от размера
фото и объёма работы). Для экспериментов можно переключить модель в `.env`
на `claude-haiku-4-5` — дешевле, но качество разбора ниже.
